# Стратегия хостинга для проекта SFMShop

## Сравнение вариантов хостинга

### VPS (Virtual Private Server)
**Примеры:** DigitalOcean, Linode, Vultr

**Преимущества:**
- Полный контроль над сервером
- Низкая стоимость (от $5/мес)
- Гибкость настройки

**Недостатки:**
- Нужно управлять сервером самостоятельно
- Нет автоматического масштабирования
- Требуются знания администрирования

**Подходит:** Небольшие проекты, проекты с особыми требованиями

---

### Cloud (AWS, Google Cloud, Azure)
**Примеры:** AWS EKS, Google Cloud Run, Azure AKS

**Преимущества:**
- Автоматическое масштабирование
- Высокая доступность (99.9%+)
- Гибкость ресурсов
- Множество сервисов (БД, кэш, очереди)

**Недостатки:**
- Высокая стоимость при росте нагрузки
- Сложность настройки
- Зависимость от провайдера

**Подходит:** Средние и большие проекты, проекты с переменной нагрузкой

---

### PaaS (Platform as a Service)
**Примеры:** Railway, Render, Fly.io

**Преимущества:**
- Простота развертывания (git push)
- Автоматическое масштабирование
- Управление инфраструктурой провайдером
- Бесплатные тарифы для старта

**Недостатки:**
- Ограниченная гибкость
- Высокая стоимость при росте
- Зависимость от провайдера

**Подходит:** Быстрый старт, небольшие и средние проекты

---

## Оценка нагрузки (RPS)

### Что такое RPS
RPS (Requests Per Second) — количество запросов, которое сервер обрабатывает в секунду.

### Текущая нагрузка
- **RPS:** < 100 запросов/сек
- **Пользователи:** Небольшое количество
- **Трафик:** Низкий

### Ожидаемая нагрузка
- **RPS:** 100-500 запросов/сек
- **Пользователи:** Растущее количество
- **Трафик:** Средний

### Пиковая нагрузка
- **RPS:** До 1000 запросов/сек
- **Сценарии:** Рекламные кампании, распродажи, сезонный рост

## Выбор хостинга

### Основной вариант: Cloud + Kubernetes
**Платформа:** AWS (или Google Cloud) с Kubernetes

**Обоснование:**
- Автоматическое масштабирование (HPA) для переменной нагрузки
- Высокая доступность для интернет-магазина
- Гибкость ресурсов для роста проекта
- Интеграция с PostgreSQL, Redis, мониторингом

### Альтернатива для старта: PaaS
**Платформа:** Railway или Render

**Обоснование:**
- Быстрое развертывание без настройки инфраструктуры
- Бесплатный тариф для тестирования
- Автоматический деплой из GitHub

---

## Стратегия масштабирования

### Горизонтальное масштабирование
- **HPA (Horizontal Pod Autoscaler):** автоматическое масштабирование на основе CPU/памяти
- **Минимум реплик:** 2 (отказоустойчивость)
- **Максимум реплик:** 10 (пиковая нагрузка)
- **Триггер:** CPU > 70%

### Кэширование
- Redis для кэширования частых запросов
- Снижение нагрузки на БД

### Мониторинг
- Отслеживание RPS и latency через логи
- Алерты при превышении порогов
- Интеграция с Sentry для отслеживания ошибок
